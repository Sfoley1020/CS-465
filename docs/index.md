# Professional Self-Assessment
When I started the Computer Science program at SNHU, I was mainly interested in cybersecurity. I wanted to understand how systems are attacked and how to protect them. As I moved through courses like CS-260, CS-350, and CS-465, I realized that I also really enjoy building software, not just securing it. Working on projects like Travlr Getaways showed me that I like taking an idea, turning it into working code, and then improving it over time. This capstone and ePortfolio bring those pieces together by showing that I can design, implement, and secure a full-stack application in a way that prepares me for professional work.

Throughout the program I gained experience collaborating in different ways. In many classes I participated in group projects, and discussion-based feedback where I had to share my code, explain my decisions, and respond to suggestions. Outside school, my current role involves working closely with sales reps, vendors, and technical staff to build accurate quotes and solutions for customers. Those experiences helped me understand how different people look at the same system from different angles (technical, business, and user-focused). In my capstone code review, I approached the walkthrough the same way I would if I were talking to a teammate or manager: I tried to be clear about what the code does, why certain decisions were made, and where I saw opportunities to improve it.

Communication has been another big part of my growth. At the beginning of the program, I mostly focused on “does this code run,” but I was not always thinking about how to explain my work to someone else. As I progressed, I wrote design documents, testing summaries, and now enhancement narratives and this self-assessment. Recording the code review video pushed me to slow down and talk through the logic, instead of just clicking around in the editor. At work, I write professional emails and quotes for customers, so I’ve learned to be clear, direct, and organized in my writing. Putting my ePortfolio together allowed me to use those skills to lay out my work so that someone who has never seen Travlr Getaways before can still understand what it does and how the enhancements improved it.

My understanding of data structures and algorithms has also grown throughout the program. In CS-260 and related classes, I worked with arrays, lists, maps, recursion, and other core structures. I learned to think about time and space complexity instead of only aiming for any working solution. In the capstone, I applied this mindset to my backend logic for Travlr Getaways. For the algorithms enhancement, I created a centralized validation function and a shared error-handling pattern for the trip controller. These changes turned scattered, repetitive checks into a clean, reusable algorithm that enforces consistent rules for incoming data. This work showed me that algorithmic thinking is not just for homework problems, but it directly affects how reliable and maintainable a real application can be.

On the software engineering and database side, Travlr Getaways is the best example of my progress. When I first worked on it in CS-465, I was learning the MEAN stack and figuring out how the Angular front end, Express backend, and MongoDB database fit together. For the capstone, I went back with more experience and improved the system design in several ways. For the software design enhancement, I replaced the static customer travel page with a dynamic Handlebars view that uses live data from the REST API, so the customer site now reflects the same trips the admin site manages. For the algorithms enhancement, I refactored the trip controller to use centralized validation and a consistent data flow. For the database enhancement, I strengthened the Mongoose schemas, tightened validation, and reinforced admin-only access to modify trip data. Together, these changes make the application more consistent, secure, and maintainable.

Security has been an important thread throughout my coursework. My cybersecurity-related classes taught me to think like an attacker and to look for weak points in design, not just in code. In Travlr Getaways, I applied this mindset by using environment variables to protect sensitive values, enforcing JWT authentication for admin operations, and carefully validating data before it reaches the database. The centralized validation logic, role-based access control, and improved schema design all help prevent malformed or unauthorized changes to the data. I know there is always more to learn in security, but this project helped me turn the “security mindset” outcome into concrete changes that reduce risk in a real system.

The three artifacts in my ePortfolio are all based on this one application, on purpose. Using the same project for software design, algorithms, and databases shows how the different areas of computer science connect in practice. The software design enhancement focuses on how the customer-facing page is structured and how it consumes live data from the REST API. The algorithms enhancement focuses on the backend logic that validates and handles trip data before it is stored or sent back to the client. The database enhancement focuses on the schema, validation rules, and secure access to the underlying MongoDB collections. Together with the code review video and this self-assessment, they give a complete picture of how I approach building, improving, and securing software instead of treating each part as a separate task.

Looking ahead, I still see myself somewhere between software development and cybersecurity. I enjoy writing and refactoring code, but I also care a lot about how secure and reliable that code is in production. In the near term, I plan to use this ePortfolio when I apply for roles that involve full-stack or backend development, especially in environments where security matters. Long term, I would like to grow into positions that focus on secure coding practices or application security. Completing the Computer Science program and building this capstone ePortfolio has shown me that I can learn new tools, work with a larger existing codebase, and clearly explain my work to others. That gives me confidence as I take the next steps in my career in the computer science field.
